# 本机音乐 — 服务、客户端与接线

宠物的音乐功能：环上的第 7 个按钮播放**你机器上的**音乐，宠物跟着节拍轻微起伏，
宠物自己说话时音乐自动闪避。本文记录**已实现的样子**，以及每条设计决定背后的原因。

> 这份文档由实施前的方案（`docs/music-plan.md` 的前身）改写而来，方案里的预测与最终实现不一致的
> 地方一律按实现改了 —— 包括那条"40–180 Hz 取平均"的算法，它实测会让律动恒为 0。

## 1. 两个半边

```
浏览器 (ui-pet 客户端)                        宿主 (dsh web 进程)
┌────────────────────────────────┐            ┌──────────────────────────────────────┐
│ PetWidget.tsx  环按钮 / 音乐条  │            │ pet-music.mjs  (DSH host 插件)       │
│  ├─ music.ts   播放器 / 歌单    │  HTTP      │  node:http  127.0.0.1:8791           │
│  ├─ audioBus.ts 混音 / 闪避 / 节拍│◀─────────▶│   GET /health                        │
│  └─ localTts.ts 神经语音 ────闪避─┼────────────│   GET /v1/music/tracks[?refresh=1]  │
└────────────────────────────────┘            │   GET /v1/music/stream/<id>  (Range) │
                                              │   GET|PUT /v1/music/roots            │
                                              └──────────────────────────────────────┘
                                                          │ 扫目录 / 读 ID3 / 读 MP4 原子
                                                          ▼
                                                    D:\Musics（+ 用户添加的目录）
```

**服务是被动的**：它不写任何配置文件，曲库根目录由客户端在启动后 `PUT` 给它，而客户端的
"记住哪些目录"存在宠物自己的 prefs store（`dsh.pet.prefs`）里。配置只有一份。

**服务是进程内的**：它不像 Python 语音服务那样需要 spawn 子进程 —— `node:http` 本来就是
非阻塞的，所以 `dispose` 只要 `server.close()`，卸载插件不可能留下孤儿进程。

## 3. 协议

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | `{ok, version, roots, missing, trackCount, scannedAt, scanning}`；客户端的自动发现 |
| GET | `/v1/music/tracks[?refresh=1]` | 曲库；默认走 60s 缓存，`refresh=1` 强制重扫 |
| GET | `/v1/music/stream/<id>` | 单曲；支持 Range、`HEAD`、`ETag`、`Accept-Ranges` |
| GET/PUT/DELETE | `/v1/music/roots` | 读/写扫描根。`PUT {"roots":[...]}` 会等重扫完成再回 200；**空数组一律 400**（否则一个 bug 就能让服务什么都不扫）；`DELETE` = 回到这个服务被配置时的那些目录 —— 那份列表只有服务自己知道 |

> `DELETE` 不是对称性洁癖：客户端的"恢复默认"是把偏好清空（`roots: []` 表示"听服务的"），
> 而它**说不出**服务配置里的目录名。所以要有一个由服务自己恢复自己的入口。
> 也正因为 `DELETE` 不在 CORS 安全方法里，OPTIONS 预检必须带上它（`test-music-server.mjs` 有断言）。

曲目对象（**不含文件路径**）：

```jsonc
{ "id": "4dda3bf0c124", "title": "下山", "artist": "", "album": "", "genre": "", "year": "",
  "extension": ".mp3", "bytes": 2775711, "hasVideo": false, "hasPicture": false, "root": "D:\\Musics" }
```

### 为什么 id 是哈希

`id = sha1(绝对路径小写).slice(0,12)`。流请求**只接受 id**，由服务端查表换回路径 ——
路径穿越在协议层就不可表达。`assertServable` 是同一扇门上的第二把锁：文件必须仍是普通文件，
且 `realpath` 后仍在某个 root 之内（防符号链接被掉包）。

### 为什么 Range 是硬需求，不是优化

`.mp4` 常把 `moov` 原子放在文件尾部。没有 `Accept-Ranges`，浏览器**根本拿不到时长**。
实测（`_probe/probe-mp4-path.cjs`）：4,661 KB 的文件 12 ms 拿到时长，浏览器发的请求是
`0-4772541`、`4718592-4772541`、`262144-4772541` —— 它主动跳到了尾部。
另一个细节：Chromium 用的是**开放式** Range（`bytes=0-`、`bytes=4718592-`），
解析器必须支持"只有起点没有终点"。

## 4. 元数据

按扩展名分派两条纯函数路径，读不到就退到文件名：

| 家族 | 读取器 | 说明 |
|---|---|---|
| `.mp3` 等 | `parseId3` | ID3v2.2/2.3/2.4；编码 0/1/2/3 全支持；跳过压缩帧、跨过扩展头；`APIC` 只标记不解码 |
| `.mp4/.m4a/.m4b/.aac` | `parseMp4Tags` | `moov > udta > meta > ilst`，取 `©nam/©ART/©alb`；`data` 原子 type 1(UTF-8)/2(UTF-16)；兼容 QuickTime 那种没有版本字的 `meta` |
| 兜底 | `artistTitleFromName` | `歌手 - 歌名` / `歌手-歌名` / `9420_麦小兜` 三种形态，靠"拉丁字母=艺人、纯数字=曲名"加权判定 |

`.m4a/.mp4` 用的是 MP4 原子**不是** ID3 —— 早期方案对 `.m4a` 去读 ID3 是设计缺陷，已修正。

## 5. 音频总线（`audioBus.ts`）

宠物原本就有一条音频路径（神经语音的 `Audio` 元素），音乐是第二条。与其让两边互相知道，
不如都走这条总线 —— 它拥有三样**只应该存在一份**的东西：

1. 一个 `AudioContext`（浏览器要求用户手势才能起，所以是惰性创建）；
2. 一个音乐 `GainNode` —— "宠物说话时把音乐压下去"因此是**一个函数调用**；
3. 一个 `AnalyserNode` —— 节拍动画的输入。

`mediaSource(element)` 是接缝：`createMediaElementSource` 对一个元素一生只能调一次，
调第二次会抛异常，且失败的调用会把元素**变成哑巴**。所以节点按元素缓存，
并且拿不到可用 context 时宁可**不接**（有音乐、没律动），也不接一半。

### 闪避

`duck(reason)` / `unduck(reason)` 用**原因集合**计数：宠物朗读和麦克风开启是两个原因，
音乐要等到两个都清掉才回升。`localTts.ts` 在每句话开始 `duck('speech')`、
结束（含取消路径）`unduck('speech')`。

实测（真浏览器、真 WebAudio）：gain 从 `1.0` 在 ~400 ms 内降到 `0.25`（仍能听见），
解除后在 ~800 ms 内回到 `0.997`。两条原因叠加时，清掉一条仍保持 `0.25`。

### 节拍

`musicLevel()` **取 40–180 Hz 这个频段里最强的那个 bin**，不是平均值。
第一版取平均，实测在一条真实音轨上（整体峰值 −73 dBFS）低频读数恒为 **0** ——
频段里绝大多数 bin 是空的，平均等于把信号除以周围 bin 的数量。取峰值之后同一条音轨
能量从 `0.026` 变成 `0.313`；用 80 Hz 测试音验证 bass 读数 `0.70` 且 `beat=true`。

调用点在 `PetWidget.tsx` 的 `requestAnimationFrame` 里，**直接写 sprite 容器的
`transform`**，不进 React state —— 为了一个装饰性动画让整个浮窗 60 fps 重渲染不值得。
宠物正在干活时幅度降到 25%（干活时乱蹦看起来像 bug，不像跳舞）。

## 6. 客户端行为

- **永远不自动播放**。浏览器拒绝没有手势的 `play()`，而拒绝的结果和"文件坏了"长得一模一样。
  所以刷新后只恢复"上次那首停在哪"，等一次点击。
- **一个按钮就是一个开关**：环上第 7 个按钮点击 = 播放/暂停，长按 = 下一首。
- **音乐条**（曲名 + `3/27` + 进度线 + ⏮ ⏸ ⏭ + 循环 + 随机 + 关闭）。
  它和气泡共用 hover 显示，但有自己的 hover 状态 —— 否则指针从宠物移向控件的路上它就会消失。
- **音乐条可以拖走、可以关掉**（见下）。
- **失败都有名字**：`no-service`（附上该跑哪条命令）、`denied`（浏览器拦了自动播放）、
  `decode`、`unsupported`、`empty`、`unknown`。不存在"转圈"这种状态。
- **语音口令**：`放歌 / 暂停 / 下一首 / 关掉音乐 / 大声点 / 小声点 / 循环播放 / 随机播放`。
  这批词和 `hush`（别说了）**不共用任何措辞** —— "别说了"是让宠物闭嘴，"别放了"是关音乐。

### 布局：为什么音乐条长这样（别再改回去）

第一版音乐条是**一行**：标题 + 七个按钮，自然宽度约 270px，失败文案还允许换行。
结果是三重塌方，用户截图里能看到：文字和气泡叠在一起、文字被按钮挤成一条缝、
整条还溢出到屏幕右边 16px。

现在的约束和结论是实测出来的（`_probe/shot-layout.cjs`，真组件 + 真 CSS + 真浏览器）：

| 约束 | 结论 |
|---|---|
| 环形按钮把整个角色围住 → **角色上方每一寸都在某个按钮的带里** | 气泡本来就和最上面两个按钮重叠（一直如此），所以"条压住按钮"不是新问题 |
| 两条**文字**叠在一起才是真正的 bug | 条只留**一行短文案**，完整说明进 `title` 和 console |
| 宠物停在离右下角 18px 处 → 以宠物中心对齐时**右边只剩一半宽度** | 条**横向平移**到视口内（实测 `760..958`，右侧留 12px），不是压窄它 |
| 一行放不下（270px > 可用宽度） | 拆成两行：上面文字 + 进度，下面控件一行，自然宽度约 198px（七个控件） |
| 条和气泡同在角色上方那一带 | **条显示时气泡让位**（`showSpeech` 里 gate 掉），同一时刻只有一条文字 |

不要"顺手"把这些改回一行、让失败文案换行 —— 会立刻退回截图里那个样子。

平移那条是**第七个控件逼出来的**：原来的做法是给条下发一个按余量算的 `max-width`，
但控件是固定尺寸的（`flex: 0 0 auto`），条被压窄时按钮会溢出自己的圆角框、飘在页面上。
现在 `max-width` 只留 CSS 的 `min(300px, 100vw - 24px)`，位置由 widget 每次渲染算一次平移量：
条**未平移时**的左边缘夹进 `[12, innerWidth - 12 - 宽度]`，宽度超过可用空间时钉左边。
`ResizeObserver`（内容变宽：曲名、文件夹面板）+ `resize` + **每次渲染**都重量一次 ——
最后一条是因为宠物自己动的时候（拖宠物）也必须跟着重算，而它不一定触发前两者。
平移量是派生值，从不持久化：拖动自己会夹取，这个只负责"停靠在角落时放不下"的情况。

### 拖动与关闭

- **整条都是把手**：按住条的任意位置（标题那行）拖动即可。按在**按钮上**不算拖动 ——
  `onBarPointerDown` 遇到 `button` 直接 return，所以"下一首"不会被拖成"搬家"。
  位置存成**相对锚点的偏移**（`musicBarOffset`，不是绝对坐标）：宠物被拖走时，条跟着走。
- **`pointer capture` + `touch-action: none`**：指针移出条之后仍然归它，触屏上也不会上滚页面。
  代价是拖拽期间 `mouseleave` 不派发，所以松手时由 `onBarPointerUp` 自己判断指针落在
  宠物或条上（落在空白处才收起），否则"拖到屏幕中间松手"会直接消失。
- **夹取用 `BAR_EDGE`（12px）**：拖动夹取和平移夹取用同一个数字，两处不会互相打架。
- **`--music-dx/--music-dy` 而不是直接写 `transform`**：进场动画 `musicIn` 也要写 `transform`，
  把偏移放进变量里两者才能共存 —— 复用 `speechIn` 会在 200ms 内把偏移抹掉（`speechIn` 里
  `translateX(-50%)` 是硬编码的）。
- **`X` = 停止 + 收起**，不是"仅停止"。收起之后**不会自己回来**：再把手移回宠物也不显示，
  否则这个按钮看起来就像没起作用。唯一的入口是**浮动音乐按钮** —— 关着的时候它的提示词
  变成"打开播放机"，点一下只把播放机放回屏幕、**不发声**（刚关掉的人要的是播放机，不是声音；
  要放再点一次）。为了这一下**一定有东西出现**，重开时条会被 `barPinned` 钉住：即使还没选歌，
  它也会带着"还没有选歌。"和 transport 出现，而不是什么都不显示。
- **一个例外**：关掉之后**新出现的失败**会把条叫回来 —— 失败只可能由用户自己要音乐引起，
  而"没人看见的失败等于没有这个功能"。已经在屏幕上、然后被 `X` 关掉的那个失败**不会**回来
  （否则 `X` 就会在最需要它的那一屏上失效）。判据是**转变**（`none → 某值`），不是状态。
- **语音让放歌不会把条叫回来**：刚说过不想看它，就不该被语音顶回来；要控制就点浮动音乐按钮
  （按钮始终在环/抽屉里）。
- **关闭时如果音乐在放，先说"关掉音乐了"，否则说"播放机收起来了"** ——
  两条文案不同，因为做的是两件事（`shot-layout.cjs` 分别断言）。
- 当前曲目停在 `X` 之后仍留着（`index` 不变），所以重新打开还能看到它、按 ▶ 从头放。
- **已知边角**：夹取只在拖动时做。把条拖到右边之后再缩小窗口，它可能有一角在视口外 ——
  宠物自己的位置也是这个行为（不在 resize 时重新夹取），想改就两边一起改。

### 换播放目录

条上第 4 个按钮（📁）打开一块**面板**，它贴在同一条的上方：

- 第一行是**服务正在扫的目录**（全文在 tooltip 里；面板换行而不是把条撑宽）。
  取的是服务回报的 `roots`，不是偏好 —— 偏好为空表示"听服务的"，客户端说不出那些目录名，
  照着偏好印会一边写着"没有目录"一边放着 27 首。
- 三个动作：`换目录…`（选中的成为唯一目录）、`添加目录…`（追加，起点是**当前真正在扫的**目录，
  所以往默认配置上加一个不会把默认的丢掉）、`恢复默认`（只在有覆盖时才出现）。
- 面板是**绝对定位**的，不参与条的宽度计算：一行路径的 max-content 就是整条路径，
  留在流里一打开就会把条撑到 300px 上限。探针断言"打开面板不改变条宽"。
- 按钮禁用而不是消失：正在选目录、或宿主根本没装目录选择器时，面板上写明原因
  （`pickFolder === undefined` 是宿主没装 workspace UI），点了也不会静默失败。
- 选了不存在/不可读的目录 → 服务重扫后返回空库 → 条上显示 `empty` 失败（含目录名），不是白屏。
- **换掉的目录里正在放的那首歌会被停掉**：流的每个请求都会按**当前** roots 重新校验，
  文件已不在其中就会 404，留着放等于中途断。反向也成立：新目录里还有这首歌就继续放。
- 语音口令做不了这件事（要真手势 + 原生对话框），所以没有对应口令。

### 持久化字段

`musicUrl`、`musicRoots`、`musicVolume`、`musicLoop`、`musicShuffle`、`musicLastId`、
`musicBarOffset`。旧 store 没有这些字段是**正常情况**，一律经窄校验读取（`toMusicPrefs`
管音乐那六项，`toBarOffset` 管偏移：不是两个有限数就当"没拖过"）。字符串音量、越界值、
未知 loop、非数组 roots、半截的 `{x}`、`NaN`/`Infinity` 都有测试。

**这条规则包括在渲染里。** 目录面板第一版直接读 `prefs.musicRoots.length`，
而升级上来的 store 根本没有这个键 → 渲染抛 `TypeError` → slot 的 error boundary 把整个宠物
换成一个空 `<div>`：点一下 📁，宠物当场消失、选目录的窗口也不会出现，只能刷新页面。
现在只读 `musicPrefs.roots`（`useMemo` 出来的、窄校验过的切片）。
探针的 store 也改成**默认用旧 store 的形状**（缺 `musicRoots`/`musicBarOffset`/`stats`），
并有一条"探针 store 确实是旧形状"的元断言，防止这个覆盖悄悄失效。

## 7. 还没做（诚实清单）

- **曲库浏览器**：不能翻列表、不能搜歌。选曲目前靠"下一首/随机"和语音口令。
- **目录的删除/排序**：面板能换、能加、能恢复默认，但不能从列表里单独去掉一个
  （多目录时只能"恢复默认"再重来）。
- **封面**：`hasPicture` 已经标出来了，但服务端不读 `APIC`/`covr`（会把响应撑大几十倍）。
- **视频画面**：`.mp4` 默认只出声。真要放画面得另做可关闭的小窗 —— 视频元素一有画面就会
  变成指针事件目标，可能挡住页面其他区域，所以不能铺满。
- **音乐相关成就**：8 个成就里还没有音乐项。
